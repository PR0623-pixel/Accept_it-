# S01 — 게임 상태 전환 구조 정리

## 목적과 범위

기준 소스: `Accept_it-(20261120-192027).zip` (사용자 제공 최신 브랜치). 기존 게임 흐름·WebSocket JSON 계약을 유지하면서 **DEBATE → MODERATOR_DECISION** 종료 경로를 재사용할 수 있도록 정리한다.

**이번 단계에 포함됨**

1. `RoomGameState.finishDebateIfActive()` 신설: 종료 사유와 관계없이 동일한 상태 정리 수행. `synchronized`, 첫 전환에만 `true`, 중복/다른 단계에서는 `false` 반환.
2. 기존 `endDebate(moderatorId)`는 참가자/사회자/단계 검증 이후 공통 메서드를 호출. 이미 판정 단계인 사회자의 중복 요청은 오류 대신 `false`로 무시한다.
3. 종료 시 `phase = MODERATOR_DECISION`, `itemEndsAt/speech/lastSpeakerId/pendingRebuttal/pendingRebuttalCardId = null`.
4. 미처리 반론 예약 카드가 있다면 종료 과정에서 카드를 돌려준다. 이미 진행한 발언의 카드 사용 상태는 유지한다.
5. WebSocket `END_DEBATE`는 전환이 실제로 일어났을 때만 `ROOM_STATE`를 방 전체에 보내고, 각 연결에 본인 `HAND`만 재전송한다. 중복 호출 시 추가 브로드캐스트하지 않는다.
6. 상태 모델·WebSocket 회귀 테스트를 추가한다.

**이번 단계에서 하지 않음**

- S02: 타이머 스케줄러, 타임아웃 검사 및 시간 만료 자동 호출.
- S03: 한쪽 카드 소진 여부 판정, 진행 중인 발언/반론 보류 조건 및 자동 호출.
- S04: 카드 사용의 DB 트랜잭션 정합성 전반 및 반론 승인·거절 시 HAND 동기화 종합 수정.
- S05/S06: DB 게임 종료/결과 보존·복구.
- S09: 구형 REST `/api/debate/{roomId}/finish` 통합·폐기 및 WebSocket 경로 통합.

## 공통 전환 계약

```java
boolean changed = state.finishDebateIfActive();
if (changed) {
    sockets.broadcastDebateFinished(roomCode);
}
```

- **선행조건:** 호출자가 현재 종료 사유에 적합한 조건을 검증할 것. `finishDebateIfActive()`는 타이머 만료나 카드 소진을 직접 확인하지 않는다.
- **동시성:** 같은 게임 상태를 `synchronized`로 보호하므로 여러 종료 트리거가 동시에 발생해도 `true`는 최대 한 번만 반환된다.
- **결과:** 전환이 완료되면 `DECIDE_ITEM`을 통한 사회자 판정이 가능하고 신규 발언·반론 요청은 단계 검사에서 거절된다.
- **대기 반론:** 미처리 예약 카드만 반환한다. 이미 진행된 일반 발언 카드나 승인된 반론 카드는 반환하지 않는다.

### S02 연결 시

종료 시각을 서버에서 검증한 뒤 `finishDebateIfActive()`를 호출한다. `true`인 경우에만 `broadcastDebateFinished()`로 알린다. 시간 만료와 수동 종료가 경쟁하더라도 한 번만 전환되어야 한다.

### S03 연결 시

진영별 손패 카드 소진을 검증하고, **`speech == null` 및 `pendingRebuttal == null`인 경우에만** `finishDebateIfActive()`를 호출한다. 한쪽 카드가 모두 소진되어도 마지막 발언과 접수된 반론은 마친 다음 종료한다. 반론 묵살로 반환된 카드는 소진으로 계산하지 않는다.

## 수동 WebSocket 검증

1. 방 생성 → 3인 역할/Ready 설정 → 게임 시작 → 두 객원이 서로 다른 찬반 선택하여 `DEBATE` 진입.
2. 사회자가 `{"type":"END_DEBATE","payload":{}}` 전송.
3. 모든 연결의 `ROOM_STATE.phase`가 `MODERATOR_DECISION`이고 `itemEndsAt`, `speech`, `lastSpeakerId`, `pendingRebuttal`이 `null`인지 확인.
4. 각 연결에서 자기 손패의 `HAND` 메시지 수신 및 다른 플레이어 손패 노출이 없는지 확인.
5. 같은 `END_DEBATE`를 다시 전송해도 중복 `ROOM_STATE` 또는 `HAND`가 전송되지 않는지 확인.
6. 객원이 `END_DEBATE`를 요청하면 `ERROR`를 받고 게임 단계는 유지되는지 확인(새 게임에서 재시험).

## 유의 사항

- 현재 구형 REST `DebateService.finishDebate()`는 이 인게임 WebSocket 종료 흐름과 **별도의 코드**이며 DB `RoomStatus.FINISHED`를 직접 변경한다. 사용자 정의 S09 구조 정리 대상이므로 이 패치에서는 변경하지 않았다. 실제 인게임 토론 종료는 WebSocket `END_DEBATE`를 사용할 것.
- 기존 `RoomGameState`는 서버 메모리에 존재하며 자동 타이머·재시작 복구는 아직 없다.
- 압축본에는 비밀정보나 `.env`를 포함하지 않았다.
- 패치 생성 환경에 Gradle 의존성 캐시가 없어 전체 Gradle 테스트 실행은 하지 못했다. 로컬 테스트 결과를 기준으로 S01 완료 여부를 확정할 것.
