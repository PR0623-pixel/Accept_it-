# R01 — 닉네임 수신 및 검증 (2026-11-18)

## 범위
- 프론트 `MainPage.tsx`의 닉네임 입력(`maxLength=10`, 공백만 입력 불가)과 맞춰 서버 검증 추가.
- `POST /api/rooms/{roomCode}/join`: JSON `{ "nickname": "홍길동" }` 수신 추가.
- 기존 `?playerName=홍길동` 형식도 기존 테스트/클라이언트 호환을 위해 임시 유지.
- `RoomService.joinRoom`에서 공백 정리, 빈 이름·길이 초과·제어문자 거부.
- 유효성 실패 시 HTTP 400 `{ "code": "INVALID_NICKNAME", "errorMessage": "..." }`.
- Validator / Service / Controller 단위 테스트를 추가함.

## 현재 규칙
| 구분 | 동작 | 근거 |
|---|---|---|
| 빈 문자열 / 공백만 입력 | 거부 | `frontend/src/pages/MainPage.tsx` |
| 닉네임 길이 | 앞뒤 공백 제거 후 1~10 (Java UTF-16 길이) | `MainPage.tsx` input `maxLength=10` |
| 앞뒤 공백 | 제거 후 저장 | `MainPage.tsx`의 `.trim()` |
| 중간 제어문자 | 거부 | 서버 입력 안정성 방어 |
| 닉네임 중복 | **정책 미확정, 중복 검사 미적용** | 원본 체크리스트 R01은 중복 정책 요구, 프론트 명세에는 규칙 없음 |
| 미입력 자동 생성 여부 | **팀 확인 필요**. 현재 프론트는 필수 입력을 요구하므로 API도 400 응답 | 원본 체크리스트 R01의 기획 쟁점 |

## 이번 범위에 포함하지 않은 것
- `POST /api/rooms`에서 Host 플레이어 생성·닉네임 영속화: **R02**.
- 방 코드 발급 충돌 재시도: **R03**.
- 방 입장 응답을 `{roomCode, playerId}`로 변경, 상태별 404/409: **R04/X01**.
- 같은 방의 닉네임 중복 허용 여부와 비교 방식: **팀 설계 확정 후 R01 완료 처리**.
- 프론트 오류 객체의 `message` 필드 호환: **X01** (현재 백엔드는 `errorMessage`).
- 방 3명 제한의 동시성 보장: **R05**.

## 검증
```powershell
.\gradlew.bat clean test
.\gradlew.bat bootRun
```
Swagger UI에서 `POST /api/rooms/{roomCode}/join`에 JSON `{ "nickname": "홍길동" }` 전달.

- 성공 시 현재 API 호환성 때문에 **숫자형 `playerId`**만 반환함.
- 유효하지 않은 닉네임이면 **400 / INVALID_NICKNAME**.
- 테스트는 기존 환경 구성과 별개로 실행 가능하도록 Mockito/MockMvc 기반으로 작성함.

## 주의
- 이번 R01 패치는 스키마 변경이 없어 **새 Flyway 마이그레이션이 필요하지 않음**.
- 프론트의 실서버 모드 전체 연동은 R02/R04/X01이 완료되어야 가능함.
