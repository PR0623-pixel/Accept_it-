# S03 — 한쪽 진영 카드 소진 시 토론 종료

## 기준 소스와 범위

- 기준: `Accept_it-(20261120-214335).zip` (S01 + S02 반영 버전).
- 규칙: 현재 물품의 PRO/CON 가운데 **어느 한쪽이라도 사용 가능한 손패가 0장**이 되면 토론 종료 조건을 충족한다.
- 다만 **진행 중인 일반 발언/승인된 반론 및 미처리 반론 신청**을 먼저 마무리한 뒤 `MODERATOR_DECISION`으로 전환한다.
- S02 정책을 유지해 **물품 전체 제한 시각이 우선**한다. 발언 중이거나 반론 대기 중이라도 물품 시간 만료 시 즉시 종료한다.
- 기존 S01 `finishDebateIfActive()`를 재사용하며, 종료 요청은 중복 적용하지 않는다.
- 카드 **콘텐츠/정식 데이터는 추후 팀이 DB에 입력**한다. 이번 단계에서는 DB 구조, 마이그레이션, 카드 콘텐츠를 변경하지 않는다.

## 1. 구현 사항

| 변경 영역 | 내용 |
|---|---|
| `RoomGameState.hasExhaustedSide()` | 양측 GUEST의 현재 손패가 모두 배분된 후 PRO/CON 각각 미사용 카드가 0장인지 계산. 어느 한쪽 소진 시 `true` |
| `RoomGameState.finishDebateIfCardsExhausted()` | `speech`와 `pendingRebuttal`이 모두 없고 소진 조건을 충족할 때만 공통 종료 호출 |
| `RoomGameState.endSpeech()` | 일반 발언 또는 승인된 반론이 끝나는 시점에 종료 조건을 재검사하고 `boolean`으로 실제 종료 여부 반환 |
| `RoomGameState.decideRebuttal()` | 승인 시 반론 발언까지 대기; 묵살 시 카드 반환 후 소진 여부 재검사 및 실제 종료 여부 반환 |
| `RoomGameState.expireTimers()` | 발언/반론 시간 만료 시 소진 상태 재검사. 유휴 상태에서 소진한 경우도 주기적 폴링으로 감지. 전체 토론 마감 우선 |
| `LobbyWebSocketHandler` | 종료 여부에 따라 `broadcastDebateFinished()`(`ROOM_STATE` + 개인별 `HAND`) 또는 단순 `ROOM_STATE` 전송. 묵살 시 반환된 카드의 `HAND`를 **요청자에게만** 재전송 |
| 기존 S02 테스트 | 일반 시간 만료 테스트가 카드 소진 규칙과 섞이지 않도록 카드 한 장씩 추가해 기존 시간 테스트 의도 유지 |

카드는 한 라운드에서 소진했더라도 다음 물품으로 이월되지 않는다. 이미 구현된 `decideItem()`의 손패 초기화와 다음 라운드 DB 재배분 동작을 수정하지 않았다.

### 세부 동작 예시

1. PRO 1장 / CON 3장 → PRO가 자신의 마지막 카드로 `START_SPEECH`: PRO 미사용 0장, **발언 진행 중이므로 DEBATE 유지**.
2. PRO가 `END_SPEECH` 또는 발언 제한 시각에 도달: 반론 대기가 없다면 **MODERATOR_DECISION**.
3. PRO가 마지막 카드로 발언 중 CON이 반론을 신청: 반론 승인·묵살 결정까지 종료 보류.
4. 승인 시 승인된 반론이 끝나야 소진 여부를 재검사; 묵살 시 반론에 예약된 카드를 돌려준 뒤 재검사.
5. 양측 카드 배분 도중 잠시 손패가 비어 있어도 **카드 소진으로 간주하지 않음**.
6. 같은 진영에 투표하여 토론을 생략한 경우 소진 검사를 적용하지 않음.

## 3. 적용 및 자동 검증 (Windows PowerShell)

S02가 반영된 `feat/game-flow-stabilization` 브랜치에서, 로컬 수정사항을 먼저 커밋 또는 백업한 다음 ZIP의 파일 구조 그대로 프로젝트 루트에 덮어쓴다.

```powershell
Expand-Archive -LiteralPath ".\AcceptIt_S03_카드소진_토론자동종료_패치.zip" -DestinationPath "." -Force

# S03 테스트
.\gradlew.bat test --tests "*RoomGameStateCardExhaustionTest" --tests "*GameTimerServiceCardExhaustionTest" --tests "*LobbyWebSocketHandlerCardExhaustionTest" --rerun-tasks

# 전체 테스트 (S01, S02 회귀 포함)
.\gradlew.bat clean test

# 테스트 리포트
start .\build\reports\tests\test\index.html
```

테스트를 위해 DB가 필요한 다른 통합 테스트가 있다면 Docker MySQL을 먼저 기동한다.

```powershell
docker compose up -d
.\gradlew.bat bootRun
```

## 4. 수동 WebSocket 검증

Postman **Desktop**에서 사회자 1명, 객원 2명으로 동일 방 접속한다. 웹 브라우저 주소창에 `ws://`를 직접 입력하지 않는다. `VITE_USE_MOCK=false`가 설정된 경우에만 프론트 화면을 통해 실제 백엔드를 시험할 수 있다.

1. 방 설정을 `cardsPerItem=1`, `maxItems=2`, `itemSeconds=180`, `speechSeconds=20`, `rebuttalSeconds=10`으로 설정한다.
2. MODERATOR 1명과 GUEST 2명 역할 선택, 전원 Ready, Host `START_GAME`.
3. 객원들이 각각 `PRO`와 `CON` 투표 → `DEBATE` 및 개인별 `HAND` 수신.
4. PRO가 자신의 실제 `cardId`로 `START_SPEECH` → PRO `HAND`에 `used=true`. 이때 **즉시 판정 단계로 가면 안 된다**.
5. PRO가 `END_SPEECH` 메시지 전송 → 추가 사회자 명령 없이 세 참가자에게 `phase=MODERATOR_DECISION`의 `ROOM_STATE` 및 각자 본인의 `HAND` 수신.
6. 위 과정을 **CON이 마지막 카드로 발언하는 경우**에도 반복한다.
7. 새 방에서 미처리 반론을 만든 뒤 사회자의 승인/묵살을 시험한다. 반론 묵살 시 반환된 카드는 **신청자 HAND의 `used=false`**로 바뀌어야 한다.
8. 사회자가 `DECIDE_ITEM`으로 다음 라운드에 진입하면 기존 `HAND`가 비워지고, 두 객원이 새로 찬반 투표한 후 **다음 물품의 DB 카드**로 다시 배분되어야 한다.
9. `END_SPEECH` 중복, 타이머 만료 중복으로 추가 판정 이벤트가 발생하지 않아야 한다.

WebSocket JSON 예시:

```json
{"type":"START_SPEECH","payload":{"cardId":101}}
```

```json
{"type":"END_SPEECH","payload":{}}
```

`101`은 예시 카드 ID로, 서버에서 지급된 본인 손패의 실제 ID를 사용해야 한다.

### 통과 기준

- 한쪽 마지막 카드의 **발언이 종료된 이후**에만 카드 소진 판정이 일어난다.
- 반론 승인/묵살과 미처리 요청 처리가 종료를 부당하게 앞당기지 않는다.
- 서버 타이머가 자동으로 마지막 발언을 끝내는 경우에도 판정으로 넘어간다.
- `MODERATOR_DECISION` 상태를 **한 번만** 브로드캐스트한다.
- 다음 라운드에서는 새로운 손패와 새로운 소진 상태를 사용한다.
- 정식 카드 콘텐츠나 Flyway DB 스키마는 변경되지 않는다.

## 5. 검증 환경의 제약과 다음 단계

- 본 패치 작성 환경에서는 **Java 21로 핵심 `RoomGameState` 코드를 별도 컴파일해 신규 상태 테스트 13개 + 기존 S01/S02 상태 테스트 16개, 총 29개를 실행하여 모두 통과**했다. 이 검증은 Spring Boot/Lombok 및 JUnit 환경을 간단한 로컬 스텁으로 대체한 **핵심 로직 한정** 검증이며, 실제 Gradle 전체 테스트의 통과를 뜻하지 않는다.
- Gradle Wrapper의 외부 배포본 다운로드가 네트워크 제한으로 실패하여, **18개 신규 테스트 가운데 WebSocket 3개와 타이머 서비스 2개는 프로젝트 Gradle에서 직접 실행하지 못했다.** Windows에서 반드시 `clean test` 및 수동 WebSocket 검증을 수행한다.
- **S04에서 보완할 항목:** 발언 요청 실패 후 DB 카드가 먼저 `used=true`가 되는 문제, 메모리/DB 카드 상태의 원자적 동기화 및 실패 시 복원, 모든 경합 상황 검증. 본 S03은 그 기존 경로를 전면 수정하지 않는다.
- DB에 정식 카드를 팀이 등록하기 전까지 기존 시작 경로의 임시 상황 카드는 테스트용으로만 취급한다.
