# R07 — 로비 나가기 (일반 참가자)

## 범위
- R06 조회 기능과 R05 DB 행 잠금을 재사용한다.
- `POST /api/rooms/{roomCode}/leave`, JSON `{"playerId":"2"}` → HTTP 204.
- 방 코드는 대소문자 구분 없이 처리한다.
- 일반 참가자 `Player` 레코드를 삭제한다. 이로써 `countByRoom`, `findByRoom`, Ready 계산 대상에서 빠진다.
- Host는 R08 정책 결정 전까지 `409 HOST_LEAVE_PENDING`으로 차단한다.
- 시작된 방에서는 `409 ALREADY_STARTED`; 방 없음 `404 ROOM_NOT_FOUND`; 해당 방에 없는 플레이어 `404 PLAYER_NOT_IN_ROOM`.
- `ROOM_STATE` 브로드캐스트는 WebSocket 서버 구현 단계에서 연결해야 한다. 프론트엔드 `rest.ts`에는 leave API가 없으므로 현재 REST 엔드포인트는 검증·향후 연동용이다.
- 별도 DB 마이그레이션 없음. R07은 연결 종료를 퇴장으로 간주하지 않는다(재접속 고려).

## 검증
1. `./gradlew.bat clean test` 및 `./gradlew.bat test --tests "*RoomServiceLeaveTest"`.
2. Swagger에서 Host 방 생성 → Guest 2명 입장 → `GET /api/rooms/{roomCode}` 3명 확인.
3. Guest ID로 `POST /api/rooms/{roomCode}/leave` → 204 확인.
4. GET 조회 시 Guest가 없어지고 인원이 2명인지 확인. 새 Guest가 입장할 수 있어야 한다.
5. 동일 ID로 재퇴장 → 404 `PLAYER_NOT_IN_ROOM`.
6. Host ID로 퇴장 → 409 `HOST_LEAVE_PENDING`, Host 유지.
7. 게임 상태를 IN_PROGRESS로 만든 테스트 방에서는 409 `ALREADY_STARTED`.

### 주의
프론트엔드에는 아직 퇴장 REST 호출이 없고 WebSocket 로비 연동도 미구현이다. 따라서 이 단계는 서버 상태 처리만 검증하며, 자동 ROOM_STATE 전파는 완료로 주장하지 않는다.
