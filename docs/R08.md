# R08 — Host 로비 퇴장 시 방 폐쇄

## 결정된 정책
- 대기 중(`WAITING`)인 방에서 **일반 참가자**가 퇴장하면 R07대로 해당 `Player`만 삭제한다.
- **Host**가 퇴장하면 그 방의 모든 플레이어와 `Room`을 같은 트랜잭션에서 물리 삭제한다.
- 폐쇄된 방의 코드는 더 이상 조회하거나 입장할 수 없다(`404 ROOM_NOT_FOUND`).
- `IN_PROGRESS`, `FINISHED` 상태의 퇴장은 기존처럼 `409 ALREADY_STARTED`로 거절한다. 게임 중 연결 끊김/재접속 정책은 별도로 다룬다.
- 방 폐쇄 시 별도 방장 이양을 수행하지 않는다.

## API (R07과 동일)
`POST /api/rooms/{roomCode}/leave` + JSON `{"playerId":"1"}` → 성공 시 `204 No Content`.

현재 프론트엔드 `src/api/rest.ts`에는 퇴장 API가 정의되지 않았으며, WebSocket의 `ROOM_STATE`/방 폐쇄 알림도 후속 단계 작업이다. **R08은 REST 기반 DB 상태 처리까지만 완료**하는 범위이다.

## 외래 키와 동시성
- `room.host_player_id → player.id`, `player.room_id → room.id`의 순환 외래 키가 있으므로 **Host 참조 NULL 처리 + flush → 방 플레이어 전체 삭제 + flush → Room 삭제** 순서를 유지한다.
- `RoomService.leaveRoom()`는 `@Transactional`로 원자성을 보장한다. 실패 시 변경을 모두 롤백한다.
- R05와 동일한 `findByRoomCodeForUpdate()`로 방 행을 잠가 같은 방의 입장·퇴장 경쟁을 직렬화한다.
- R08에서 방을 삭제할 때 다른 방의 `Player`나 전체 물품 템플릿을 삭제하지 않는다.
- WAITING 로비는 아직 카드·토론 기록이 없다는 게임 진행 전제를 사용한다. 과거 테스트 데이터를 이용해 WAITING으로 강제로 상태를 돌려놓은 방에 카드·토론 FK가 남아 있으면 삭제가 DB 제약으로 거절될 수 있다. **새 방으로 검증할 것.**

## 적용
1. R07 검증 완료 상태에 이 ZIP 파일을 프로젝트 루트에 압축 해제한다.
2. 오래된 `HostLeavePendingException.java`는 더 이상 사용하지 않으므로 **선택적으로 삭제**한다. 삭제하지 않아도 컴파일과 실행에는 지장이 없다.
3. `./gradlew.bat clean test` 또는 `./gradlew.bat test --tests "*RoomServiceLeaveTest" --tests "*RoomControllerLeaveTest"`.
4. `./gradlew.bat bootRun` 후 Swagger에서 검증.

## Swagger + MySQL 검증 절차
1. 새 방 생성: `POST /api/rooms {"nickname":"Host"}` → `roomCode`, `hostPlayerId`가 될 `playerId` 확인.
2. Guest 1명 이상 입장, `GET /api/rooms/{roomCode}`로 목록 확인.
3. **Host**의 ID로 `POST /api/rooms/{roomCode}/leave {"playerId":"HOST_ID"}` → HTTP 204.
4. 같은 방에 GET → HTTP 404 `ROOM_NOT_FOUND`; 같은 코드로 Join → HTTP 404 `ROOM_NOT_FOUND`.
5. DB에서 `SELECT * FROM room WHERE room_code='ABC123';` → 0행 확인.
6. Host 및 Guest ID를 포함하여 `SELECT * FROM player WHERE id IN (HOST_ID,GUEST_ID);` → 0행 확인.
7. 다른 새 방을 생성하고 Guest 퇴장 → HTTP 204, 남은 로비는 유지되는지 확인.
8. `IN_PROGRESS`로 만든 **별도 테스트 방**에서는 Host 퇴장이 `409 ALREADY_STARTED`인지 확인.

## 보안 및 알림 관련 후속 작업
- 이 API는 현재 `playerId`를 요청 본문으로 받아 퇴장자를 지정한다. **요청자 본인 인증은 아직 없으며**, Host ID를 아는 다른 요청자가 Host 퇴장을 위조할 수 있다. 실제 공개 배포 전 T02 인증/권한 확인이 필요하다.
- 다른 로비 참가자에게 실시간 방 폐쇄를 알리는 WebSocket 처리는 아직 구현되지 않았다. 추후 프론트엔드와 이벤트 계약을 맞춰 연결해야 한다.
