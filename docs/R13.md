# R13 — 게임 설정 다섯 항목 저장

## 범위와 기준
- 현재 브랜치 `Accept_it-(20261118-201150).zip` 기준. R01~R12 기존 로직 유지.
- 체크리스트: 카드 개수, 일반 발언 시간, 반론 시간, 물품당(라운드당) 시간, 최대 물품(라운드) 수 모두 저장·조회.
- 프론트 현재 `RoomSettings`에는 `cardsPerItem`, `itemSeconds`, `maxItems` **3개만 정의**되어 있고,
  일반 발언/반론 시간은 `SPEECH_SECONDS=120`, `REBUTTAL_SECONDS=60` 상수임.
  R13에서는 DB/로비 조회에 `speechSeconds`, `rebuttalSeconds`를 추가하되, **프론트 코드는 변경하지 않음**.
- 실제 클라이언트에서 방 설정은 `UPDATE_SETTINGS` WebSocket (기존 3개 필드)으로 보내므로
  R13에서 만든 REST 경로는 Swagger 확인용. W단계에서 WS 이벤트로 연결.

## DB 매핑 (총 5개)
| 외부 필드 | DB `room` 컬럼 | 기본값 | 단위 |
|---|---|---:|---|
| cardsPerItem | max_card_count (기존) | 3 | 장/객원/물품 |
| speechSeconds | speech_seconds (V5 추가) | 120 | 초 |
| rebuttalSeconds | rebuttal_seconds (V5 추가) | 60 | 초 |
| itemSeconds | turn_time_limit (기존) | 300 | API는 초, DB는 분(5) |
| maxItems | max_items (V5 추가) | 3 | 물품(라운드) 수 |

Flyway `V5__add_room_game_settings.sql`은 기존 방/설정값을 삭제하지 않고 새 세 컬럼을 기본값으로 채움.
서버에서 스키마 검증(`ddl-auto: validate`) 중이므로 V5 배포 후 실행할 것.

## 임시 REST 검증
- `PUT /api/rooms/{roomCode}/settings` → 성공 `204` (설정 저장),
  오류 `400 BAD_REQUEST` / `403 NOT_HOST` / `404 ROOM_NOT_FOUND` / `409 ALREADY_STARTED`.
- `GET /api/rooms/{roomCode}` → `settings`에 위 다섯 값 응답.
- 요청 JSON:

```json
{
  "playerId": "11",
  "cardsPerItem": 4,
  "speechSeconds": 150,
  "rebuttalSeconds": 75,
  "itemSeconds": 480,
  "maxItems": 5
}
```

- 방 코드와 Host 플레이어 ID는 `POST /api/rooms` 반환값 사용.
- 변경 시 기존 mock 규칙처럼 해당 방의 **전원 Ready=false**.
- 요청이 WAITING 상태여야 하며, Host ID가 아니면 `403 NOT_HOST`.
- R13에서는 양수와 `itemSeconds`의 60초 단위만 확인. **최종 1~5/180~1200 등 범위 검증은 R14**.
- R15의 정식 Host 인증 연동 전까지는 요청 JSON `playerId`를 임의로 위조할 수 있는 개발용 API이므로 공개 서비스에 노출하면 안 됨.

## 로컬 점검
```powershell
.\gradlew.bat clean test
.\gradlew.bat bootRun
```

1. 새 방 생성 → GET 설정 기본값 `3,120,60,300,3` 확인.
2. Host로 PUT 설정 5개 수정 → HTTP 204.
3. GET 설정 5개 변경 확인 및 기존 플레이어 Ready=false 확인.
4. DB에서 `SELECT room_code,max_card_count,speech_seconds,rebuttal_seconds,turn_time_limit,max_items FROM room;` 확인.
5. Guest playerId로 PUT → 403 NOT_HOST, 값 유지.
6. itemSeconds 299 또는 필드 누락 → 400 BAD_REQUEST, 값 유지.
7. 기존 테스트 95개 + R13 신규 테스트 확인.

## 분리된 후속 작업
- R14: 5개 설정의 확정 최솟값/최댓값/기본값과 변경 입력 검증.
- R15: 실제 WebSocket 연결자의 인증된 playerId로 Host 권한 확인, 변경 이벤트 연동.
- R17/W: 설정 수정 즉시 ROOM_STATE 브로드캐스트.
- 게임 발언/반론 타이머가 이 필드를 실제로 사용하게 연결하는 것은 G/D/B 단계에서 수행.
- **요청에 따라 `POST /api/rooms/{roomCode}/role`의 roomCode 서비스 전달은 R13에서 수정하지 않음.**
