# R12 — 역할 변경과 Ready 정합성 (R11 Ready 규칙 개정 포함)

## 확정 정책
1. 로비 역할: `NONE/GUEST/MODERATOR`, 정원 `MODERATOR` 1명, `GUEST` 2명 (R09/R10 유지).
2. 역할을 선택한 참가자는 **방에 1명 또는 2명만 있어도** `ready=true`로 준비할 수 있다. Ready는 개인 상태이며 게임 시작과 별개다(사용자 확인 정책).
3. `NONE`은 `ready=true`가 불가(`409 ROLE_REQUIRED`). 역할이 없어도 `ready=false`는 가능하다.
4. 성공한 `SET_ROLE`은 **같은 역할 재선택을 포함해** 본인의 Ready를 `false`, 해당 물품의 stance를 `null`로 초기화한다. 나머지 참가자의 Ready는 변경하지 않는다. 기존 프론트 목 서버와 일치하는 R09/R10 동작이다.
5. ROLE_FULL 등 **역할 선택 실패 시** 기존 role/Ready/stance가 전부 유지된다.
6. 전원 Ready가 되어도 R12는 게임을 자동으로 시작하지 않는다. **정확히 3명, 사회자 1 + 객원 2, 전원 Ready** 검증과 트랜잭션 시작은 R16/G03에서 처리한다.
7. Host 여부는 Role/Ready와 독립적이며, 역할을 NONE으로 바꿔도 Host 권한은 유지된다.

## 구현
- `RoomService.setReady`: 역할 선택 검증은 유지, **3명 미만 차단 로직 제거**. 기존 Room → Player 잠금 순서와 WAITING 제한 유지.
- `RoomService.selectRole`: R10에서 이미 구현한 **성공 시 Ready/stance 초기화, 실패 시 불변** 로직을 유지. R12에서는 상호작용 테스트로 보증한다.
- `RoomController`: Swagger의 Ready API 설명과 409 오류 목록에서 NOT_ENOUGH_PLAYERS 제거.
- `RoomServiceReadyTest`: 1명/2명 준비 성공, 3명 미만에서도 게임 상태 유지 테스트.
- `RoomServiceRoleReadyConsistencyTest`: 전원 준비 후 역할 변경, 같은 역할 재선택, 정원 초과 실패, 혼자 준비 후 NONE 변경, 준비 취소 검증.
- `RoomControllerReadyTest`: 구형 Ready 인원 부족 오류 테스트 제거.
- Flyway/DB 변경 없음. 기존 `/api/rooms/ready` 역할 선택, `/api/rooms/{roomCode}/ready` 준비 토글을 그대로 사용.

## 검증 절차 (Swagger)
1. 아래 Gradle 명령으로 전체 테스트 실행.
2. `POST /api/rooms` `{ "nickname": "Host" }` → 방 생성, playerId 확인.
3. `POST /api/rooms/ready` `{ "playerId": <Host ID>, "role": "MODERATOR" }` → HTTP 200.
4. **Host 1명만 있을 때** `POST /api/rooms/{roomCode}/ready` `{ "playerId": "<Host ID>", "ready": true }` → HTTP 204, `GET /api/rooms/{roomCode}`에서 Ready=true.
5. 객원 1명 입장·GUEST 역할 선택·Ready=true → HTTP 204, **2명이어도** 대기 상태 유지.
6. Host가 `POST /api/rooms/ready`로 `MODERATOR`를 다시 선택 → 200, Host Ready=false로 초기화, 객원의 Ready는 true 유지.
7. 객원 2명이 모두 `GUEST` 자리를 채운 다음 Host가 `GUEST`로 변경을 시도 → 409 ROLE_FULL, 기존 Ready/role 변경 없음.
8. 역할을 `NONE`으로 선택하면 Ready=false; 다시 Ready=true 시도 → 409 ROLE_REQUIRED.
9. 세 명의 역할·Ready가 모두 채워져도 R12에서는 자동 게임 시작 없음 (R16/G03 책임).

## 프론트엔드·통신 담당자 전달
- `frontend/BACKEND_CONTRACT.md`와 `frontend/src/api/mockServer.ts`에 남아 있는 `SET_READY`의 `NOT_ENOUGH_PLAYERS` 조건은 **현재 사용자 확정 정책과 달라 수정 필요**. 여기서는 프론트 담당자의 변경분을 덮어쓰지 않도록 백엔드/문서만 수정했다.
- 실제 WebSocket `SET_ROLE`과 `SET_READY`는 각각 `RoomService.selectRole`과 `RoomService.setReady`를 연결하고, 성공 후 `ROOM_STATE`를 브로드캐스트하면 된다(R17/W단계).
- 기존 REST 검증 경로는 개발용이므로 공개 운영 시 별도 세션 인증/권한 검증이 필요하다.
