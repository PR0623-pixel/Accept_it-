# R11 — Ready 상태 독립 토글

## 기능 범위
- 역할 선택(`SET_ROLE`)과 별개로 `ready=true`(준비), `ready=false`(준비 취소)를 저장한다.
- 기존 R09/R10 임시 REST 역할 선택 `POST /api/rooms/ready`는 **역할 선택 전용**으로 유지한다.
- R11 임시 Swagger REST `POST /api/rooms/{roomCode}/ready`를 새로 추가한다.
  - Body: `{ "playerId": "12", "ready": true }` 또는 `{ "playerId": "12", "ready": false }`
  - 성공: HTTP **204 No Content**
  - `playerId`는 방 생성/입장 응답의 문자열 ID이며 정수 형태여야 한다.
- 실제 프론트의 계약은 WebSocket `SET_READY { ready }`이다. R11의 REST 경로는 **검증/연결 전 임시 API**이고 프론트 `rest.ts` 변경은 필요 없다.

## 검증 규칙 (frontend/src/types.ts, api/mockServer.ts)
1. 방이 존재하고 `WAITING`(프론트 `LOBBY`)이며, 요청자가 그 방의 참가자여야 한다.
2. `ready=true`일 때: 플레이어의 로비 역할이 `NONE`(또는 null)이면 **409 ROLE_REQUIRED**. 에러 메시지: `역할 칸으로 먼저 이동하세요.`
3. `ready=true`일 때: 인원이 **3명 미만이면 409 NOT_ENOUGH_PLAYERS**. 에러 메시지: `인원이 부족합니다. 3명이 모여야 시작할 수 있습니다.`
4. `ready=false`는 역할이 `NONE`이거나 인원이 줄어도 허용한다(단 대기 로비·소속 검증은 유지).
5. 여러 번 같은 상태로 설정해도 성공하는 멱등 동작이다. 다른 플레이어의 Ready, 역할, stance는 변경하지 않는다.
6. 방이 없으면 `404 ROOM_NOT_FOUND`, 다른 방/없는 참가자면 `404 PLAYER_NOT_IN_ROOM`, 진행 중이면 `409 ALREADY_STARTED`, 잘못된 ready 값은 `400 BAD_REQUEST`.
7. 오류 발생 시 기존 Ready를 변경하지 않는다.

## 동시 요청 처리
- R05/R10처럼 **방 행을 먼저 PESSIMISTIC_WRITE 잠금**, 이후 참가자 행을 잠금 조회한다.
- 역할 변경, 입장/퇴장과 Ready 요청을 같은 방 잠금으로 직렬화한다. MySQL REPEATABLE READ에서 구형 목록 스냅샷이 남지 않도록 참가자 목록은 잠금 조회한다.
- Flyway 추가 및 DB 스키마 변경 없음. `Player.isReady`를 재사용한다.

## R16 및 WebSocket 담당자 참고
- 프론트 목 서버는 세 명 전원이 Ready가 되는 즉시 게임을 시작하지만, 현재 백엔드 체크리스트에서 **R16(시작 조건) / G03(게임 시작 트랜잭션)**이 따로 배정되어 있다. 이번 R11은 **Ready 상태 저장만** 구현하고 자동 시작/AI 호출은 의도적으로 구현하지 않는다. 통합 시 R16/G03에서 전원 Ready 감지와 시작 전환을 연결해야 한다.
- WebSocket `SET_READY` 처리자는 접속 세션의 `playerId`, 방 코드와 payload의 `ready`를 이용해 `RoomService.setReady(roomCode, playerId, ready)`를 호출하고, 성공 시 최신 `ROOM_STATE`를 전원에게 전송한다(R17/W단계). 실패 시 요청자에게 `ERROR {code,message}`를 전송한다.
- REST는 `playerId`만으로 요청자를 지정하는 **개발용 경로**여서 인증된 세션과 연결되기 전에는 신뢰할 수 있는 권한 검증 수단이 아니다.

## 검증 순서
1. PowerShell 프로젝트 루트에서 ` .\gradlew.bat clean test ` 실행
2. 3명이 입장하기 전 Ready=true → `409 NOT_ENOUGH_PLAYERS` (역할은 먼저 선택).
3. 3명 입장 후 `NONE` 역할 Ready=true → `409 ROLE_REQUIRED`.
4. `POST /api/rooms/ready`에서 Host를 MODERATOR, 나머지 두 명을 GUEST로 선택.
5. `POST /api/rooms/{roomCode}/ready`에서 각자 ready=true → `204`, 조회 시 Ready=true.
6. 일부가 ready=false → `204`, 조회 시 해당 플레이어만 Ready=false.
7. 해당 플레이어가 다른 역할을 재선택하면 Ready=false로 초기화됨(R09/R10 기존 동작).
8. 3명 모두 Ready여도 R11에서는 Room 상태가 LOBBY로 유지(시작 처리는 R16).
