# R15 — Host 전용 게임 설정 변경 권한

## 목표
- **R15 완료 기준:** 방 설정 변경은 그 방의 Host 플레이어만 할 수 있다.
- 기준 소스: `Accept_it-(20261118-201150).zip` + 검증 완료된 R13/R14 패치.
- R13의 단순 `room.hostPlayer.id == playerId` 비교를 확장해 **요청 플레이어의 방 소속 여부까지 확인**한다.
- 로비 역할 `NONE`/`GUEST`/`MODERATOR`와 **Host 권한은 독립적**이다. 예를 들어 `MODERATOR`가 방장이 아니면 수정 불가, `GUEST`인 Host는 수정 가능.

## REST 설정 변경 (기존 계약 유지)
- `PUT /api/rooms/{roomCode}/settings`, body의 `playerId`와 다섯 설정 필드 사용.
- 서버는 **유효한 설정값 검사 → 방 행 잠금 → WAITING 확인 → playerId의 실제 room_id 조회 → Host 여부 확인 → 저장 및 전원 Ready 해제** 순서로 처리.
- 요청의 `roomCode`는 공백 제거·대문자 변환 후 실제 방을 조회한다.
- R05/R10/R11과 동일하게 먼저 Room row lock을 획득하여 방 상태/구성 변경과 설정 수정을 직렬화한다.
- 모든 설정이 유효하고 Host 권한이 확인된 뒤에만 다섯 값을 저장하고 해당 방 멤버의 Ready를 초기화한다.

| 조건 | HTTP | 코드 | 상태 변경 |
|---|---|---|---|
| 본인 방의 Host, WAITING | 204 | 없음 | 설정 저장, 전원 Ready=false |
| 같은 방의 일반 멤버(로비 MODERATOR 포함) | 403 | NOT_HOST | 없음 |
| 없는 playerId / 다른 방 소속 playerId | 404 | PLAYER_NOT_IN_ROOM | 없음 |
| 방 없음 또는 잘못된 방 코드 | 404 | ROOM_NOT_FOUND | 없음 |
| WAITING 외 상태 | 409 | ALREADY_STARTED | 없음 |
| 설정값 오류 | 400 | BAD_REQUEST | 없음 |

## 보안상 한계 — 중요
- **이번 단계는 권한 확인(authorization)이지 로그인·연결자 신원 인증(authentication)이 아니다.**
- 현재 임시 REST API는 요청자가 `playerId`를 임의로 작성할 수 있다. 다른 사람이 실제 Host의 playerId를 알아내어 요청하면 서버는 그 사람을 Host로 착각할 수 있다. 따라서 **공개 환경에서 안전한 Host 인증이라고 말할 수 없다.**
- 프론트 현재 WebSocket `UPDATE_SETTINGS`는 body의 playerId가 아닌, WS 연결의 플레이어 정체성을 사용해야 한다. W 단계에서는 인증/서명된 세션 또는 신뢰 가능한 연결자 신원에서 playerId를 추출하고 `RoomService.updateSettings(roomCode, trustedPlayerId, settings)`에 전달한다. 단순 WS query parameter `playerId`만으로는 신원 위조 방어가 되지 않으므로 서버 측 검증 방법을 별도로 정해야 한다.
- 인가 검사를 HTTP Controller만이 아니라 공통 서비스에 유지하면 WebSocket에서도 재사용할 수 있다.

## 유지 사항과 이후 단계
- R14의 설정 기본값 및 허용 범위, `itemSeconds` 60초 단위, 오류 메시지, 전원 Ready 해제 정책 유지.
- DB/마이그레이션 변경 없음. 프론트 코드와 REST DTO/경로 변경 없음.
- 요청에 따라 `POST /api/rooms/{roomCode}/role`의 roomCode 서비스 미전달 문제는 **이번에도 변경하지 않음**.
- R16: 참가자 3명, 역할 1+2, 전원 Ready, Host 시작 요청 검증.
- R17/W: 실제 `UPDATE_SETTINGS`, ROOM_STATE 이벤트와 연결자 인증 방식 확정.
- 발언/반론 시간 설정 범위는 R14 문서에 기재한 후속 변경 가능 항목 그대로 유지.

1. Guest 로비 역할인 Host가 설정 변경 → 204, GET으로 저장값 확인 / 전원 Ready 해제.
2. MODERATOR 역할이지만 비Host인 참가자의 설정 변경 → 403 `NOT_HOST`.
3. 다른 방에 소속된 플레이어 ID / 없는 ID → 404 `PLAYER_NOT_IN_ROOM`.

5. 오류 발생 시 기존 설정과 Ready가 바뀌지 않음.
6. `WAITING` 외 상태 → 409 `ALREADY_STARTED`.
